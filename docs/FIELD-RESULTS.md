# Field results

The design's own rule (DESIGN.md section 11): a number measured on the repo the oracles
were tuned on is an upper bound; the number that carries weight is the one weftgate
produces on code it has never seen. This page is the latter. It is regenerated by
hand from the commands below; the fixture numbers live in the self-test.

Date: 2026-09-12. weftgate at commit `eef26b0` (v0.1.0, pre-release). Six public
repositories, each shallow-cloned at the commit shown, unmodified.

## Method

For each repository, from weftgate's own virtual environment (that is, **not** from the
project's environment, so nothing the project depends on is installed unless it
happens to be a weftgate dev tool):

```bash
weftgate index --rebuild          # timed: full build
weftgate index                    # timed: no-op sync
weftgate audit --format=json      # every claim in the repo through the live gate
weftgate eval mutate --seed 13 --count 4   # up to 4 injected breakages per oracle, on a copy
```

The mutation harness counts three things separately: **detected** (any review or
reject on the injected breakage), **blocked** (a reject), and **suggested** (blocked
and the correct name is among the did-you-mean suggestions). A mutation that is
detected but not blocked is reported as *soft*, never hidden.

### What the reviews are

Reviews never block. In these six repos they are, by count:

- `fastapi-users`: 38 routes included through `fastapi_users.get_*_router(...)` calls
  (computed at runtime; weftgate cannot resolve them statically) and 36 imports that are
  either installed-but-undeclared dev tools in test files, names provided under a
  different distribution name (`beanie` via `fastapi-users-db-beanie`), or names absent
  from a manifest that has no lockfile.
- `dispatch`: 33 `starlette` imports (a transitive dependency of `fastapi`, absent from
  `pyproject.toml`, which has no lockfile), a handful of names provided by
  differently named distributions (`atlassian` via `atlassian-python-api`), one
  runtime-computed router, one dynamic env read.
- `full-stack-fastapi-template`: one env read with a computed key.

## Mutation harness: does the gate catch what it claims to

| Repository | Mutations | Detected | Blocked | Suggested | Misses | Soft (detected, not blocked) |
|---|---:|---:|---:|---:|---:|---|
| full-stack-fastapi-template | 9 | 9 | 8 | 8 | 1 | `axios` typo in the frontend, which has `package.json` but no lockfile |
| fastapi-realworld-example-app | 6 | 6 | 6 | 6 | 0 | |
| fastapi_production_template | 4 | 4 | 4 | 4 | 0 | |
| node-express-realworld-example-app | 4 | 4 | 4 | 4 | 0 | |
| fastapi-users | 8 | 8 | 4 | 4 | 4 | four import typos; `pyproject.toml` only, no lockfile |
| Netflix/dispatch | 12 | 12 | 10 | 10 | 2 | two `sqlalchemy` typos in migrations; `pyproject.toml` only, no lockfile |

Every injected breakage was detected. Every one that was not blocked is the same
situation: the repository declares its dependencies in a **manifest** (`pyproject.toml`
or `package.json`) without committing a **lockfile**. A manifest lists direct
dependencies only, so a name absent from it may be transitive, and absence is not
proven. weftgate reviews with the suggestion attached (`did you mean sqlalchemy?`) instead
of rejecting. Committing a lockfile (`uv.lock`, `poetry.lock`, `package-lock.json`, or a
fully pinned `requirements.txt`) turns those into rejects.

There is a second way absence becomes provable without a lockfile: when weftgate runs
inside the project's own environment. If the mandatory dependencies of the project
are installed in the interpreter running weftgate, the environment demonstrably matches
the project, and a name installed nowhere is rejected. Re-running `fastapi-users`
from a virtual environment with its dependencies installed:

| Repository | Environment | Mutations | Detected | Blocked | Suggested | Misses |
|---|---|---:|---:|---:|---:|---:|
| fastapi-users | weftgate's own venv | 8 | 8 | 4 | 4 | 4 |
| fastapi-users | the project's venv | 8 | 8 | **8** | **8** | **0** |

The audit inside the project's venv is unchanged (0 rejects): nothing in the repo is
actually broken, and the extra evidence only sharpens verdicts on the *injected*
breakage.

## What the field run changed in weftgate

Running on these repos before publishing found and fixed six false rejects that the
fixture could not have shown. They are recorded here so the next oracle author knows
what real code does:

1. A route decorator on a **function parameter** (`def test(app: FastAPI): @app.get(...)`)
   rejected because parameters were not bindings.
2. A monorepo with `backend/pyproject.toml` could not resolve `from app.api.routes import
   login` because only the repo root, `src/`, and `lib/` were source roots.
3. `tests` imported inside `backend/tests/` reviewed as a "nested package" for the same
   reason.
4. Docusaurus specs (`@site/static`, `@theme/Layout`, `@docusaurus/Link`) rejected as
   phantom packages; they are resolved by the framework.
5. Transitive imports (`starlette` via `fastapi`) rejected when only a manifest exists.
6. `import motor` in documentation snippets under `docs/src/` rejected; documentation
   is illustrative, so claims from `docs/` are soft.

## Reproducing

```bash
git clone --depth 1 https://github.com/Netflix/dispatch && cd dispatch
pip install weftgate            # after the rename; or pip install -e /path/to/weftgate
weftgate index --rebuild && weftgate audit && weftgate eval mutate --seed 13 --count 4
```

The numbers will drift as those repositories change; the commits above pin what was
measured.
